# Usability and Accessibility Test Kit (PT6)

Use this kit with **at least 3 testers who did not build the game**. Do not coach them
through the interface. Record what you see; don't write down your opinion as if it were a
finding. Don't collect names: use P1, P2, P3.

## 1. Briefing and consent (read aloud)

> "I'm testing my phone game, not you. There are no wrong moves. Please think aloud. I won't
> help unless you are stuck for a long time. I'll write notes and may take screenshots of the
> screen only, not your face. You can stop at any time. Is that OK?"

Record: consent yes/no, tester code, age group only if needed (e.g. 18–24), has played sili-tubig before (yes/no).

## 2. Tasks

| Task | What the tester must do | Success means |
|---|---|---|
| T1 Onboarding | From the title screen, find out how to play and start Solo vs Bot | Reaches the maze without help |
| T2 Core loop | Find a "?" scroll and answer it | Opens and answers a question |
| T3 Power-up | Use a Halo-Halo cooler (press E / tap USE) | Gets the Yelo Shield |
| T4 Settings and pause | Turn the music down, then pause and resume | Both done |
| T5 Recovery | After being frozen, get unfrozen (Huling Hirit) or retry the round | Continues playing |

## 4. Accessibility checklist (check on the phone)

| Item | How to check | Result |
|---|---|---|
| Text size readable at arm's length | Questions, HUD, name tags | |
| Contrast | Yellow/white text on dark panels; red warning text | |
| Not colour-only | Roles also shown by name tags, warnings have text, minimap squares also have labels in game | |
| Touch targets ≥ 44 px | Answer buttons, RUN, USE, pause, ✕ | |
| Alternative feedback | Sound + text + vibration on tag / answer | |
| Volume control | Settings: music and sound separately | |
| Pause | Pause button + auto-pause when leaving the app | |
| Game pace | 15 s / 10–12 s answer timers; is it enough for slower readers? | |
| Input | Joystick on the right half; is it usable left-handed? | |
